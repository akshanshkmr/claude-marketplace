# JMIR Tables, Figures, Textboxes, and Multimedia Appendices

Complete reference for formatting tables, figures, textboxes, TOC images, and multimedia appendices (MAs). Based on JMIR House Style and AMA Manual of Style (11th ed).

---

## Part 1: Tables

### §1. General Table Formatting

1. **Table numbering**: Tables are numbered sequentially (Table 1, Table 2, etc.) in order of first mention in text.
2. **In-text citation**: Every table must be cited in the main text. Citations must appear in numerical order.
3. **No drawing objects**: Tables must be created using Word's built-in table feature — never use drawing shapes, text boxes, or embedded images.
4. **No hard returns**: Do NOT insert hard returns (manual line breaks) within table cells.
5. **Gridlines**: All tables should have visible gridlines for clarity.
6. **Data consistency**: Cross-check data in tables against the main text and abstract. Flag discrepancies to authors.

### §2. Table Captions

1. **Format**: `Table 1.` in **bold**, followed by a descriptive caption in **sentence case**, ending with a **period**.
2. Example: **Table 1.** Baseline demographic characteristics of participants.
3. Caption should be succinct and descriptive.
4. Do NOT include abbreviation expansions in the caption — use footnotes instead.

### §3. Column Headings

1. Use **sentence case** for column headings (capitalize first word and proper nouns only).
2. Units of measure belong in the column heading if applicable to all items in that column.
3. Format for participant counts: `Participants, n (%)` — do NOT use "No. of Participants".
4. Percent sign (%) appears **only** in the column heading, not in individual cells.

### §4. Row Headings

1. Row headings describe the data in each row.
2. **Bold** row headings that serve as **category headers** with nested subcategories.
3. P values should be placed in row headings when appropriate.
4. Units belong in row headings if applicable to all nested items.

### §5. Category Headings and Nesting

1. **Category headers** with nested subcategories must be **bolded**.
2. Subcategories are placed in rows below the category header, in a separate column.
3. The category header cell should be **merged horizontally** across all data columns.
4. Indent subcategory labels to visually indicate nesting (using spaces, not tabs).
5. Example structure:
   ```
   | Demographics              |        |        |
   |   Age (years), mean (SD)  | 45 (12)| 43 (11)|
   |   Sex, n (%)              |        |        |
   |     Male                  | 25 (50)| 22 (44)|
   |     Female                | 25 (50)| 28 (56)|
   ```

### §6. Cell Data Formatting

| Data Type | Format | Example |
|-----------|--------|---------|
| Sample size + percentage | `n (%)` | `25 (50)` |
| Mean + standard deviation | `mean (SD)` | `45.3 (12.7)` |
| Odds ratio + confidence interval | `OR (95% CI)` | `2.45 (1.23-4.89)` |
| Median + IQR | `median (IQR)` | `45 (32-58)` |
| Range | `min-max` | `20-68` |

**Rules for cells:**
- Combine related values in a **single cell** (do not split n and % across columns).
- Percent sign appears only in the column header — NOT repeated in cells.
- For hyphens in ranges within tables: use a hyphen (not en dash). When one value is negative, use "to" instead.

### §7. Empty Cells and Missing Data

| Situation | Symbol | Notes |
|-----------|--------|-------|
| Data not available | **em dash** (—) | Define in a footnote: "—: not available" or "—: data not collected" |
| Not applicable | **N/A** | Note the forward slash. Use for cells where the data category doesn't apply |
| Zero value | **0** | Use the numeral zero, not an em dash |

- If "N/A" appears in only 2-3 instances, em dashes may be used instead with appropriate footnote.
- Replace generic "N/A" for missing data with em dashes and footnotes unless there are very few instances.

### §8. Table Footnotes

1. **Symbols**: Use alphabetical **superscript** letters: ᵃ, ᵇ, ᶜ, ᵈ, etc.
2. **Order**: Assign footnote markers reading **left to right, top to bottom** through the table.
3. **No asterisks**: Do NOT use asterisks (*, **) for footnotes. Exception: systematic reviews or OR tables may use asterisks for significance.
4. **Period**: Every footnote must **end with a period**.
5. **Abbreviations in footnotes**: List all abbreviations used in the table that are not defined in the table or caption. List in **order of appearance** (not alphabetical).
6. **P values in footnotes**: Do not use `P≤.001`. Provide exact P values or use `P<.001`.
7. **Em dash definition**: If em dashes are used for missing data, include a footnote defining them.

### §9. Tables With Multi-Row Headers

- For tables with complex multi-row headers (eg, grouped columns):
  - Merge cells horizontally for group headers.
  - Use horizontal rules to separate header rows from data rows.
  - Ensure the hierarchy is clear: top-level group headers span all sub-columns.

### §10. Correlation Tables

- Correlation values and P values must appear in **separate rows** — do not combine in one cell.
- Example structure: one row for `r` values, one row for `P` values.

### §11. Data Accuracy in Tables

- **Cross-check** data accuracy and consistency between main text and tables/figures.
- In PRISMA flowcharts: verify that additions to and subtractions from the total count are correct.
- Numbers in tables should be consistent with those reported in the abstract and text.
- Flag discrepancies to the author — do not silently correct data.

## Part 2: Textboxes

### §12. Textbox Formatting

1. **Definition**: 1-column tables should be converted to **1×1 Word tables** representing textboxes.
2. Do NOT use Word's built-in drawing shapes or text boxes — use a 1×1 Word table only.
3. **Numbering**: Textboxes are numbered sequentially: Textbox 1, Textbox 2, etc.
4. **In-text citation**: Every textbox must be cited in the main text.
5. **Content**: Bullet points or numbered lists are allowed inside textboxes.
6. **No footnotes**: Textboxes do NOT have footnotes.
7. **Reference citations in captions**: Remove reference citations from textbox captions. Move them to the appropriate location in main text instead.
   - Example: Instead of `Textbox 1. Characteristics of apps [25].` → move [25] to main text: `Characteristics of the 10 most frequently reported apps [25] are briefly described in Textbox 1.`

### §13. Textbox Captions

1. **Format**: `Textbox 1.` in **bold**, followed by descriptive caption in **sentence case**, ending with a **period**.
2. Keep captions concise.

## Part 3: Figures

### §14. Figure Captions

1. **Format**: Caption in **sentence case**, ending with a **period**.
2. Do NOT include "Figure X" inside the caption text field — the numbering is handled by the system.
3. Caption should be a succinct description of the figure content.
4. **Abbreviations in captions**: Define all abbreviations used in the figure at the **end of the caption**, in **alphabetical order**, using the format: `CE: copyeditor; LE: layout editor.`
5. Caption must end with a period (after the last abbreviation expansion).

### §15. Figure Language and Quality

1. **Language corrections**: Suggest corrections in Step 1 comments. Look for red error lines under words in figures.
2. **Abbreviations in figures**: All abbreviations used in the figure must be spelled out — either in the figure itself or in the caption/legend.
3. **Reference citations in figures**: If reference citations appear in the figure or figure legend, cite them in text immediately after the first mention of the figure.
   - Example: `...as shown in Figure 1 [29].`

### §16. Figure Content Guidelines

1. Figures should be clear, legible, and high resolution.
2. Text within figures should be readable at publication size.
3. Color should be used meaningfully (not just for decoration).
4. All axes must be labeled with units of measure.
5. Legends should clearly identify all data series.
6. **Maximum file size**: 5 MB; maximum dimensions: 1200 × 1200 pixels.
7. **Figure numbers and captions** must be removed from the image file itself. Crop the image if possible; otherwise, ask the author to remove the caption from the image file and upload a revised image.
8. **Multi-part figures**: If a figure is logically split into parts, merge all parts into a **single PNG file** with parts labeled A, B, C, etc. Two unrelated figures should NOT be lumped together — upload them as separate figures (Figure 1, Figure 2).

### §16A. Mentioning Figures in Text

1. All figures **must** be mentioned by number in the text (eg, "as Figure 2 shows"). Vague expressions ("as the following figure shows" or "in the figure above") must be replaced with the exact figure number.
2. Since figures may be moved during typesetting, do NOT reference a figure's location ("in the next paragraph"). Use neutral statements.
3. When referring to multiple figures, use a **hyphen for ranges** (eg, "Figures 1-4") or list each separately (eg, "Figures 1-3, Figure 6, Figure 8"). Do NOT use words ("Figures 1 through 4") or en dashes — only hyphens are picked up by typesetting scripts.

### §16B. Forest Plots

1. Forest plots are typically generated using statistical software and may be presented as figures or tables.
2. When presented as a **figure**: reference citations corresponding to the studies in the plot **must** be cited in the figure caption.
   - Example: `Figure 1. Forest plot of 6 studies comparing the effectiveness of serious games with that of no or sham interventions on verbal learning [29,30,31-34].`
3. When presented as a **table**: reference citations should be placed alongside the authors' names in the table rows.

### §16C. Figure Footnotes

1. **Avoid footnotes in figures** wherever possible. Include extra information within the figure, its legend, or caption.
2. If footnotes are necessary (eg, for P values), use **asterisks** in the figure: `*`, `**`, `***`.
3. Maximum: **3 asterisks** and consequently **3 footnotes**.
4. Place footnote explanations at the end of the figure legend.
   - Example: `Figure 1. Study design flowchart. EHR: electronic health record; PHW: personal health worker. *P<.05, **P<.001.`

### §16D. AI-Generated Figures

1. Check whether authors have disclosed the use of an AI tool (eg, DALL-E, Midjourney) in the figure caption.
2. If not disclosed, prompt them to add:
   - The name of the AI tool used.
   - The prompt used for generating the image.
   - A reference to the source/generated image URL (added to RefCheck as a website reference).
3. AI tool usage should also be declared in the Acknowledgments section.

### §16E. Figure Extraction From Manuscript

1. **Image files/photos**: Right-click (or Ctrl-click on Mac) the image → "Save as Picture" → save as PNG → upload to Editing page.
2. **Line art/flow diagrams** (created using Word's drawing features):
   - Hide red/green wavy lines: switch off spell/grammar checks in Word, or generate a PDF/Print preview.
   - Enlarge the figure as much as the screen allows.
   - Take a screenshot (Mac: `Shift-Command-4`) and save as PNG.

### §17. Figures That Are NOT Permitted

The following types of figures are not permitted or require action:

| Figure Type | Permitted? | Required Action |
|-------------|------------|------------------|
| **Simple pie charts** | ❌ No | Convert to table, text, or multimedia appendix |
| **Complex pie charts** (multiple segments, exact values) | ✅ Yes | — |
| **Simple bar graphs** (single variable ± error bars) | ❌ No | Convert to table, text, or MA; or use line graph if data are continuous |
| **Complex bar graphs** (stacked, comparative, multi-variable) | ✅ Yes | — |
| **Word clouds** | ❌ No | Convert to table or multimedia appendix |
| **Node diagrams** | ✅ Yes | — |
| **Tables submitted as images** | ❌ No | Recreate using Insert Table in Word/Kriyadocs |
| **Copyrighted figures** | ⚠️ Action required | Provide CC license or written permission |
| **Images of research participants** | ⚠️ Action required | Provide signed consent or deidentify image |

**Additional rules:**
1. **Photographs of people** require written consent and IRB approval. Authors must include a statement under "Ethical Considerations" that explicit consent was granted. Upload consent documentation to "Other files - not for publication."
2. **Tables as images exception**: Allowed if colors/icons are essential (eg, heat maps, risk of bias assessments, forest plots).
3. **Simple charts/graphs**: Authors should provide exact values. Simple data is better conveyed in text or table format.
4. Figures that simply repeat data already presented in a table — query the author about whether both are necessary.

### §18. Copyright and Permissions

1. **Check CC license** for figures/tables from external sources:
   - If **CC BY**: Add citation and Creative Commons link. Format: `(reproduced from Smith et al [37], which is published under Creative Commons Attribution 4.0 International License [38])`
   - If **copyrighted**: Request permission from publisher. Format: `(reproduced from Smith et al [37], with permission from [publisher])`
2. Query authors for permission documentation if not provided.

### §19. Unused Figure/MA Files

- If unused figure or MA files are present on the Editing tab:
  - Ask the author if they should be included in the manuscript.
  - If not to be included: move them to the "Other" files section on the Editing tab (they should not appear in the final PDF).
  - If to be included: assign an MA number (all MAs must be numbered).

## Part 4: Table of Contents (TOC) Thumbnail Image

### §20. TOC Image

1. **Reuse existing figures first**: If the manuscript contains suitable figures (eg, screenshots of the intervention, a person using the intervention), they can serve as the TOC image without re-uploading — just note this in the layout comment.
2. **Query if no TOC**: If there are no suitable figures, query the author: "Do you have a figure you would like to use for the Table of Contents thumbnail image? If not, we can select one for you."
3. **If author does not provide a TOC image**: Leave a layout comment for the typesetter to inform them.
4. The TOC image is uploaded separately from the manuscript figures (via the article webpage "Editing" tab).

## Part 5: Multimedia Appendices (MAs)

### §21. MA Content Guidelines

1. **Numbering**: MAs are numbered sequentially: Multimedia Appendix 1, Multimedia Appendix 2, etc.
2. **In-text citation**: Every MA must be cited in the main text.
   - **Exceptions**: Reports (eg, peer-review reports) and checklists (eg, CONSORT-EHEALTH, PRISMA) may be included in the MAs section **without** citation in the paper.
   - If there are uncited appendices, these should appear **after** the cited ones.
   - If you encounter other potential exceptions, query the Team Lead – Copyediting.
3. **Captions**: Sentence case, ending with a period. Use descriptive language — avoid generic captions like "Supplementary tables" or "Supplementary materials" or "Table S1."
4. **Copyeditor's responsibility**: Copyedit MA captions directly on the assignment page (not in the Word file). Abbreviations within appendix content are NOT the copyeditor's responsibility.
5. **All MA files must be uploaded** to the JMIR website. If authors email files, upload them by clicking "Choose File" under "Upload new figure, appendix or other supplementary file" and select "Multimedia Appendix" as the type.
6. **Zipped files**: If authors zipped multiple files together, they usually need to be unpacked, reuploaded as separate supplementary files, and referred to as separate MAs. **Exception**: Multiple files all containing computer code may be left packed as one MA.
7. **"Not used" flag**: Query the author if there are appendices uploaded that are flagged as "not used" — this might be a mistake.

### §21A. Supplementary Item Naming Within MAs

1. Although multiple items may appear in a single MA file, each item (figure or table) should be named **Table S1, Table S2, Figure S1, Figure S2**, etc. within each MA.
2. When citing specific items from an MA in the main text:
   - Use the "S" prefix (Supplementary) to differentiate from main figures/tables.
   - Always specify which MA the item is in: `"...as shown in Figure S1 in Multimedia Appendix 1"` (NOT just `"as shown in Figure S1"`).
3. If renaming items is required but not done by the author in Step 2, do so for them in Step 3.

### §21B. Images as Multimedia Appendices

1. If authors provide **1-2 screenshots or images** as appendices, prefer converting them to **figures** unless the manuscript already has ≥5 figures.
2. Query authors about changing an appendix to a figure. If agreed, click "Edit," change the "Type" to "Figure," and update the reference in main text.
3. Multiple screenshots should be compiled in a **single PDF or PPT** (PDF preferred).
4. Stand-alone images as MAs should be **PNG or PDF** format, not TIFF.

### §22. Copyeditor's Responsibilities for MAs

1. Review MA captions for language, formatting, and abbreviation expansion.
2. Ensure all MAs are cited in the main text (with exceptions per §21.2).
3. Check that MA numbering is sequential and consistent.
4. Verify that required checklists are present (see §23).
5. Check for unused MA files and query authors (see §19).
6. Gloss over the document for glaring errors (eg, title page, missing tables, discrepancies with the caption).
7. Request authors to remove any cover page or title information from MA documents.

### §23. Required/Mandatory Multimedia Appendices

#### 23.1 CONSORT-EHEALTH (for RCTs)

| Requirement | Details |
|-------------|---------|
| **When required** | RCTs reporting results (eg, in an Original Paper). Protocols and proposals do NOT require a CONSORT checklist |
| **CONSORT flow diagram** | Required as a **figure** in the Results section (NOT as an MA). An attrition diagram is also required |
| **CONSORT-EHEALTH checklist** | Required as an **MA** for eHealth/mHealth trials |
| **MA caption format** | `CONSORT-eHEALTH checklist (V 1.6.x).` where x = version number |
| **Non-web-based/mHealth RCTs** | Use standard CONSORT checklist (not CONSORT-EHEALTH) |

#### 23.2 PRISMA (for Systematic Reviews)

| Requirement | Details |
|-------------|---------|
| **When required** | Systematic reviews ("Review" article type) |
| **PRISMA flow diagram** | Required as a **figure** in the Results section (NOT as an MA) |
| **PRISMA checklist** | Required as an **MA** |
| **Scoping reviews** | Use PRISMA-ScR variant |
| **Flow diagram accuracy** | Verify additions/subtractions in flow diagram match main text |

#### 23.3 iCHECK-DH (for Implementation Reports)

| Requirement | Details |
|-------------|---------|
| **When required** | "Implementation Reports" article type in **JMIR Medical Informatics** only |
| **Checklist** | iCHECK-DH checklist as an MA |

#### 23.4 Other Checklists

- Checklist names (PRISMA, CONSORT, CHERRIES, SPIRIT, STROBE, etc.) do **NOT** need to be expanded in MA captions.
- The expansion should be given in the **Abbreviations end section** instead.
- Query authors if required checklists are missing.

### §24. Peer-Review Reports

- **Required as MAs** for funded proposals and protocols in JMIR Research Protocols.
- Peer-review reports must be from the granting agency (not just ethics approval).
- Reports should be in an original letter-headed document from the funding institution (screenshots of emails or simple Word documents are not sufficient).
- Reports can be in any language; if a translation in English is available, supply it as a second MA.
- JMIR's policy is to **publish** peer-review reports unless a written notice from the funder prevents it.

### §25. Questionnaires and Other Important Tools

- Include questionnaires, survey instruments, and other important tools as MAs — **unless copyright-protected**.
- New questionnaires/scales/instruments **must** be openly accessible under a CC license.
- If copyright-protected: query the author about obtaining permission or provide alternative documentation.
- **Morisky Medication Adherence Scales (MMAS)**: JMIR strongly discourages use due to legal issues. If used, authors must upload license documentation.

### §26. Including References in MAs

- **(Revised August 2024)** References cited within an MA should have a corresponding, **stand-alone reference list within that same MA file**, even if some references overlap with the main manuscript's reference list.
- There are no specifications for the citation format within MAs (numbered or author/year are both acceptable) as long as each citation has a corresponding entry.
- **Nonoverlapping references** in MAs do NOT need to be added to RefCheck or cited in the main text.
- **Exception**: References for studies included in the main analysis (eg, included/eligible studies in a systematic review) **must** be included in the main manuscript's reference list and cited in the main text.
   - Example: `"We included 278 publications [1-278]..."` placed as close as possible to the in-text mention of the MA/Table/Figure.
- Inform the author in Step 1 if further revisions to MA references are necessary, and finalize in Step 3.

### §27. Long Tables

- Tables exceeding **1.5 pages** in the published article (approximately >3 pages in a Word document with font size 10-12 pt) should be moved to a **Multimedia Appendix**.
- Query the author about relocating overly long tables.

## Part 6: Quick Reference Checklist

### Tables Checklist
- [ ] All tables cited in text in numerical order
- [ ] Captions: bold number + sentence case + period
- [ ] Column headings: sentence case, units included
- [ ] "Participants, n (%)" format (not "No. of Participants")
- [ ] Percent sign only in header, not in cells
- [ ] Category headers bolded with correct nesting
- [ ] Cells: n (%), mean (SD), OR (95% CI) in single cells
- [ ] Em dashes for unavailable data (with footnote)
- [ ] N/A for not applicable (with forward slash)
- [ ] Footnotes: alphabetical superscripts, order of appearance, end with periods
- [ ] No asterisks for significance (except systematic reviews/OR tables)
- [ ] All abbreviations defined in footnotes
- [ ] No hard returns in cells
- [ ] P values rounded correctly per statistics guidelines
- [ ] Units in correct location (column or row heading)
- [ ] Correlation and P values in separate rows (correlation tables)
- [ ] Data cross-checked against text and abstract

### Figures Checklist
- [ ] All figures cited in text in numerical order
- [ ] Captions: sentence case, end with period
- [ ] "Figure X" NOT in caption text field
- [ ] All abbreviations defined at end of caption (alphabetical)
- [ ] Reference citations in figure/legend also cited in text
- [ ] Language corrections suggested in comments
- [ ] No red error lines in figures
- [ ] Copyright/permissions checked
- [ ] Unused files addressed

### Textboxes Checklist
- [ ] 1-column tables converted to 1×1 Word tables
- [ ] No drawing shapes used
- [ ] No footnotes
- [ ] Reference citations removed from captions (moved to text)
- [ ] Cited in main text

### MA Checklist
- [ ] All MAs cited in text
- [ ] Sequential numbering
- [ ] Captions: sentence case, period, abbreviations expanded
- [ ] Required checklists present (CONSORT/PRISMA/iCHECK-DH)
- [ ] CONSORT flow diagram as figure (not MA), CONSORT-EHEALTH as MA
- [ ] PRISMA flow diagram as figure (not MA), PRISMA checklist as MA
- [ ] Checklist names NOT expanded in captions (expansion in Abbreviations list)
- [ ] Peer-review reports included for funded proposals/protocols
- [ ] Questionnaires included unless copyright-protected
- [ ] Unused files addressed
